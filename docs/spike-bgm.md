# 技術検証: BGM、動画中のBGMの下げ、音ズレ補正

> 実施日: 2026-10-21。Linux（クラウド上のコンテナ、音声出力の機器なし）で、描画エンジン単体の自動テストにより確認した。実際のスピーカーやBluetooth機器で耳による確認はしていない。

## 1. 目的

[技術選定](tech-stack.md)の「最初に検証する技術課題」4番（音声同期とBGMフェードを破綻なく扱えるか）のうち、[動画の音声と映像の同期](spike-audio-sync.md)で対象外にした次の3点の方式を決める。

- BGMの再生（フォルダ指定、シャッフル、曲の切り替え）
- 音のある動画の間にBGMを下げ、終わったら戻す処理
- Bluetooth機器など、機器が報告するより遅れて聞こえる出力のための音ズレ補正

## 2. 方式

### BGM

| 項目 | 実装 |
| --- | --- |
| 曲の指定 | フォルダ（直下の音楽ファイル。`.` で始まるファイルは除く）か、ファイルの一覧。対応する拡張子は mp3、m4a、aac、wav、flac、ogg、oga、opus、aif、aiff、wma |
| デコード | 動画の音と同じく、1曲につき1つの `ffmpeg` プロセスで出力機器の形式（32bit浮動小数点・ステレオ）に変換し、10秒分を先に受け取っておく。次の曲は今の曲を流している間に開いておく |
| 鳴らし方 | ミキサーの「Source」（時刻から音を作る仕組み）として鳴らす。動画の音と違い、BGMは映像の時計には載せず、始まった所から流し続ける |
| 曲のつなぎ | 曲ごとにフェードイン（既定2秒）、再生、曲の終わりの手前でフェードアウト、無音（既定1秒）、次の曲。曲同士を重ねるクロスフェードはしない。調もテンポも違う曲が重なると聞き苦しく、曲の終わりは10秒先までしか分からないため |
| シャッフル | 1周ごとに全曲を1回ずつ流す順番を作り直す。周の変わり目で同じ曲が続かないようにする |
| 操作 | 一時停止（0.1秒でフェード）、次の曲へ（1秒でフェードアウト）、音量、フェードの曲線（線形／等パワー）。再生中に変えられる |
| 壊れた曲 | 飛ばして次へ進み、イベントと統計で知らせる。全曲が続けて失敗したらあきらめて無音にする |
| 曲名 | `ffmpeg` で曲のタグ（title、artist）を読む。なければファイル名を使う |

### 動画の間のBGMの下げ（ダッキング）

| 項目 | 実装 |
| --- | --- |
| 知らせ方 | スライドショーは、音のある動画の読み込みが終わり、始まる時刻が分かった時点で、その動画の音が鳴る区間（再生時刻の開始と終了）を `Ducker` でBGMに知らせる。通常は動画が始まる数秒前になる |
| 下げる時刻 | 動画が始まる時点で下げ終わっているようにする（既定1秒かけて無音まで下げる）。動画の音は話し声が多く、下がりかけの曲の上で始まると聞き取りにくいため。知らせが遅れたときは、知らせた時点から下げる |
| 戻す時刻 | 動画の終わりから既定2秒かけて戻す |
| 近い動画 | 戻している途中でまた下げる必要がある区間はまとめ、動画と動画の間で曲が一瞬だけ大きくならないようにする |
| 遅れへの対応 | 次の素材の読み込みが遅れて動画の開始が遅れたときは、区間を実際の開始時刻に動かす。長さが分からない動画は、終わりの時刻を決めずに知らせ、画面から消えた時点で終わりとする |
| 音ズレ補正との関係 | 下げる量は、音ズレ補正を含めた「その音が聞こえる時刻」で決める。動画の音と同じ時刻で下がる |

### 音ズレ補正

| 項目 | 実装 |
| --- | --- |
| 指定 | 利用者がミリ秒で指定する（-500〜1000ms）。正の値は音を早める（その時刻より後の音を今出す）。負の値は音を遅らせる |
| 先に分かる音 | 動画の音のように前もって始まる時刻が分かる音は、補正の分だけ早く鳴らし始める |
| 先に分からない音 | 始まりを補正の分だけ飛ばして鳴らす |
| 再生中の変更 | 音が飛ばないよう、補正の値に届くまで ±2% の速度で読み進める（10msの変更に0.5秒）。200msを超える変更は一度に飛ばし、合わせ直す |
| 書き出し | 書き出し用のミキサーは補正を受け付けず、常に0で動く。特定の部屋に合わせた補正が書き出したファイルに残らないようにするため |
| 合わせる手段 | テスト音（`calibration`）。一定の間隔で、画面の点滅と1000Hzの短い音（50ms）を同じ再生時刻に出す。利用者は両方が同時に感じられるまで補正の値を上げる。テスト音もミキサーを通るため、動画の音と同じように補正がかかる |

- [`crates/fluxlide-engine/src/bgm.rs`](../crates/fluxlide-engine/src/bgm.rs): BGMの曲の管理、つなぎ、ダッキング
- [`crates/fluxlide-engine/src/media/music.rs`](../crates/fluxlide-engine/src/media/music.rs): ffmpegによる曲のデコードとタグの読み取り
- [`crates/fluxlide-engine/src/audio.rs`](../crates/fluxlide-engine/src/audio.rs): 音ズレ補正、Source、フェードの曲線
- [`crates/fluxlide-engine/src/calibration.rs`](../crates/fluxlide-engine/src/calibration.rs): テスト音
- [`crates/fluxlide-engine/src/slideshow.rs`](../crates/fluxlide-engine/src/slideshow.rs): 動画の音の区間をBGMに知らせる

## 3. 確認環境

| 項目 | 内容 |
| --- | --- |
| OS | Ubuntu 24.04.5（クラウド上のコンテナ） |
| CPU | 4コア、メモリ15GB |
| GPU | なし（Mesaのllvmpipeによるソフトウェアの Vulkan） |
| 音声出力の機器 | なし |
| FFmpeg | 6.1.1（Ubuntuのパッケージ版） |

## 4. 結果

自動テスト（`cargo test -p fluxlide-engine`）で確かめた。ミキサーは、出力機器の代わりにメモリ上で波形を作る `OfflineMixer` を使った。

| 確認項目 | 結果 |
| --- | --- |
| 曲のつなぎ（フェードイン、フェードアウト、無音、次の曲） | 期待した時刻と音量になる |
| 等パワーのフェード | 中間で線形より大きく、2曲の合計の強さが保たれる |
| 次の曲へ、一時停止と再開、音量の変更 | 途切れずに変わる。一時停止中は曲もフェードも止まる |
| 動画の開始時にBGMが無音になり、終了後に戻る | 期待した通り |
| 知らせが遅れた動画、近い2本の動画、終わりが分からない動画 | 期待した通り |
| スライドショーからの知らせ | 動画の読み込みが終わった時点で、始まる予定の時刻で知らせ、遅れて始まったときは実際の時刻に動かし、画面から消えたら閉じる |
| シャッフル | 1周で全曲を1回ずつ流し、偏りがない |
| 実際のファイル（ffmpegで作ったwav・m4aと壊れたファイル）を含むフォルダ | 壊れたファイルを飛ばして流れ続ける。全曲が壊れていればあきらめたことを知らせる |
| 音ズレ補正 | 補正の分だけ早い時刻の音が出る。値の変更は飛ばずに寄っていく。大きな変更は飛ばして合わせ直す。書き出し用のミキサーは補正を拒む |
| テスト音 | 予定の時刻に鳴り、補正の分だけ早く鳴る。端がなめらかな短い音になる |

## 5. 未確認のことと次の作業

- 実際の出力機器で耳で確かめていない。macOSの内蔵スピーカー、Bluetoothのイヤホンやスピーカーで、BGMのつなぎと下げ方が自然か、テスト音で補正の値を決められるかを確かめる。
- Bluetooth機器の遅延（一般に150〜300ms程度とされる）が、補正の範囲（-500〜1000ms）と変更時の速度（±2%）で扱えるかを実機で確かめる。
- Windows（WASAPI）、Linux（ALSA、PulseAudio・PipeWire経由）の実機での確認。
- テスト音の画面側（点滅）は、上映ウィンドウにまだ描いていない。描画エンジンの合成（キャプションなど）がそろってから入れる。
- BGMを書き出しに入れる処理。書き出し用のミキサーに同じ `Source` を足せば動く作りにしてあるが、試していない。
