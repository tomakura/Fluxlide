# Fluxlide 画面草案

> ステータス: 草案 v0.5（2026-10-20）。実装前の画面設計案であり、内容は今後変わる可能性がある。

![Fluxlide](../assets/brand/fluxlide-logo.svg)

## 1. 目的

パソコンに慣れていない人でも、写真や動画を追加してそのままプロジェクターに映せることを目標にする。本書では、6つの画面の構成と、すべての画面に共通する方針、ロゴの仕様をまとめる。

## 2. 共通方針

| 方針 | 内容 |
| --- | --- |
| 設定はタブ3つ | 「写真・動画」「見た目」「音楽」を設定して「上映する」を押す流れにする。編集画面の右列の上にこの3つのタブを常に表示する。タブに番号は付けない |
| 追加すればすぐ上映できる | 表示時間10秒、トランジションはフェードを初期値にする。何も設定しなくても上映できる |
| 技術用語だけ言い換える | トランジションやループのように一般に通じる言葉はそのまま使う。同期オフセットやエンコードのような技術用語は言い換える（[7. 用語の扱い](#7-用語の扱い)） |
| 細かい設定は畳んでおく | よく使う項目だけを表示し、残りは「詳細設定」に入れる。開けばすべての項目を変更できる |
| 配置を固定する | 左に素材の並び、中央にプレビュー、右に設定を置く。どのタブを開いてもこの配置は変えない |
| 操作を取り消せる | 自動保存と「元に戻す」をいつでも使えるようにする。上映の終了には確認を挟み、取り込みに失敗した素材には理由と対処を表示する |

## 3. 画面の流れ

```text
A. ホーム → B. 編集 → C. 出力先の選択 → D. 上映中の操作（操作用の画面）
                                        └ E. 上映画面（プロジェクター等）
              └ F. 動画に書き出す
```

## 4. 各画面

### A. ホーム

起動して最初に表示する画面。

- 左側: アプリ名、「新しいスライドショーを作る」ボタン、ファイルのドロップ領域、「サンプルを開いて使い方を見る」
- 右側: 最近のスライドショー（サムネイル、最終編集日、枚数）、「ほかの場所から開く…」、自動保存の案内

設計上の判断:

1. 最初の選択肢は「新規作成」と「最近のスライドショーを開く」の2つに絞る。新規作成のボタンを最も大きくする。
2. ファイルをドラッグすると、新しいスライドショーを作って取り込みを始める。
3. 案内ツアーは入れない。サンプルの各スライドのキャプションに操作の説明を書いておき、上映しながら使い方が分かるようにする。
4. 最近のスライドショーはサムネイルで探せるようにし、保存場所を意識させない。

### B. 編集

素材の並び、プレビュー、設定を1画面にまとめる。

- 上部: スライドショー名、保存状態（「自動保存済み」）、元に戻す・やり直す、「動画に書き出す」、「▶ 上映する」
- 左列: 素材の縦一列のリスト（番号、サムネイル、タイトル、表示時間とトランジション）、「＋ 追加」、ドロップ領域
- 中央: プレビュー（上映画面と同じ描画）、再生位置、「このスライドから再生」、次の操作の案内
- 右列: タブ（写真・動画／見た目／音楽）と、選んだタブの設定

右列の内容:

| タブ | 項目 |
| --- | --- |
| 写真・動画（選択中のスライド） | タイトル、作者、説明、キャプションの表示、表示時間、トランジション。詳細設定にゆっくりズーム・表示位置・トランジションの長さ |
| 見た目（全スライド共通） | キャプションのデザイン（下帯／シンプル／カード）、ウォーターマーク（画像・位置・不透明度）、縦横比が合わない写真（ぼかし背景／黒帯／トリミング）、トランジション。詳細設定に文字サイズ・書体・カスタムトランジション（WGSL） |
| 音楽 | BGMの指定（フォルダを指定／曲を個別に選ぶ）、シャッフル再生、BGMの音量、動画の再生中はBGMを止める、音ズレ補正（テスト音で調整）。詳細設定にフェードの長さ・曲間の無音 |

設計上の判断:

1. タブを押すと、そのタブの設定だけを右列に表示する。順番どおりに操作する必要はない。
2. 取り込み中の素材は、コピーの進み具合を行ごとに表示する。コピーの完了を待たずにタイトルや説明を入力できる。
3. 開けない素材には、理由と「選び直す」「外す」のボタンを表示する。
4. プレビューは上映・書き出しと同じ描画エンジンで表示し、キャプション、ウォーターマーク、トランジションの見え方を確認できるようにする。
5. ゆっくりズームや表示位置の調整は「詳細設定」に入れる。
6. 「上映する」は常に右上に置く。上映に関わるボタンだけを赤系にして、ほかの操作と区別する。
7. 保存ボタンは置かない。変更は自動で保存し、保存の状態だけを表示する。
8. 次の操作を短く案内する。不要になったら閉じられる。
9. BGMはフォルダで指定でき、中の曲をシャッフル再生する。フォルダに曲を追加すると、次に上映するときから再生対象に入る。曲を1つずつ選ぶ方法も残す。

### C. 出力先の選択

「上映する」を押したときに表示する確認。2回目以降は前回の画面を使い、すぐに上映を始める。

- 接続された画面を図で表示する（名前、接続方法、解像度。操作に使う画面には「操作用」と表示）
- 「各画面に番号を表示」ボタン
- 進め方（自動／手動）、最後まで再生したら（ループ／最後のスライドで停止）、順番（並び順／シャッフル）
- 「次回もこの画面を使う」、「やめる」、「▶ 上映を始める」

設計上の判断:

1. 画面は図で選ばせる。
2. 「各画面に番号を表示」を押すと、各モニターに「1」「2」を数秒間大きく表示する。どの画面がどれか分からないときに使う。
3. 画面が1台ならこの確認を省き、「この画面に全画面で映します。終了するにはEscキーを押してください」と表示してから上映を始める。
4. 再生方法もここでまとめて選べるようにする。

### D. 上映中の操作

上映中に操作用の画面に表示する内容。プロジェクター側には映像だけを出力する。

- 上部の帯: 「上映中」、出力先の画面名、経過時間、「■ 上映を終了」
- 中央: 現在のスライド（大）、次のスライド、この後のスライド一覧
- 下部: 「◀ 前へ」「❚❚ 一時停止」「次へ ▶」、暗転、再生中のBGMと「次の曲」、音量、音ズレ補正
- 最下部: キー操作の一覧（← → 前へ・次へ、Space 一時停止、B 暗転、Esc 上映を終了）

設計上の判断:

1. 上映中であることと出力先の画面名を常に表示する。この帯の色は上映中にだけ使う。
2. 現在と次のスライドを並べ、手動で進めるときも次に何が映るかを確認できるようにする。
3. 主な操作は3つの大きなボタンにまとめ、キーボードでも同じ操作をできるようにする。
4. 暗転は上映を止めずに画面を黒にする。もう一度押すと元に戻る。
5. 上映の終了には確認ダイアログを表示する。
6. 再生中の曲名を表示し、次の曲に送れるようにする。音量と音ズレ補正は会場で聞きながら調整できる。

### E. 上映画面

プロジェクターや外部モニターに出力する画面。

設計上の判断:

1. 出力するのは映像、キャプション、ウォーターマークだけにする。マウスカーソルや操作ボタンは表示しない。通知などが重ならないよう、専用の全画面ウィンドウで出力する。
2. キャプションはタイトル・作者・説明の3行で、編集画面で入力した内容を使う。
3. ウォーターマークはトランジションの最中も位置と不透明度を変えない。
4. 縦横比が合わない写真は「ぼかし背景」を初期値にする。黒帯より画面が寂しくならず、トリミングと違って写真が欠けない。
5. 開始前と終了後の画面を用意し、タイトルとロゴを表示する。黒い画面のまま待たせない。

キャプションの表示仕様:

| 項目 | 内容 |
| --- | --- |
| 書体 | IBM Plex Sans JP（OFL） |
| ウェイト | タイトル Bold（700）、作者・説明 Light（300） |
| 大きさ | 1080pxの高さでタイトル 72px、作者 29px、説明 32px |
| 字間 | タイトル 0.01em、作者 0.025em、説明 0 |
| 行間 | タイトル・作者 1.2、説明 1.3 |
| デザイン | 下帯（下部に薄いグラデーション）、シンプル（左下に細い縦線と文字）、カード（右下に明るい札）、なし |
| ウォーターマーク | 右上に配置。字間を広く取った細い枠付きの表示を例とする |

### F. 動画に書き出す

同じスライドショーを動画ファイルにする。形式ではなく用途から選ぶ。

| 用途 | 設定 |
| --- | --- |
| テレビ・プロジェクター | 1920×1080 · MP4 |
| パソコン・動画サイト | 1920×1080 · 容量小さめ |
| スマホ・SNS | 縦 1080×1920 |
| 高画質 | 3840×2160 |

設計上の判断:

1. 解像度やコーデックを知らなくても用途から選べるようにする。数値は補足として小さく表示する。
2. 書き出しを始める前に、ファイルサイズと所要時間の目安を表示する。
3. 音ズレ補正は上映専用の設定で、書き出しには反映しない。この点をダイアログ内に明記する。
4. MP4以外の形式、コーデック、ビットレート、フレームレートは「詳細設定」で変更できる。

## 5. 操作画面の配色

操作画面の明暗はOSの設定に合わせる。プレビューと上映画面の背景は、OSの設定にかかわらず黒にする。

## 6. 主な配色

| 用途 | 色 |
| --- | --- |
| 選択・主要ボタン | 青（ライト `#1E5FC4` / ダーク `#72A3F2`） |
| 上映に関わる表示 | 赤系（ライト `#D93C25` / ダーク `#FF6B4F`） |
| ブランド（ロゴ） | ネイビー `#13213B`、コーラル `#E8553A` |

## 7. 用語の扱い

トランジション、キャプション、フェード、ループ、シャッフルのように一般に通じる言葉はそのまま使う。言い換えるのは次の技術用語だけとする。

| 設計上の用語 | 画面の表記 |
| --- | --- |
| メディア | 写真・動画 |
| メタデータ（タイトル・作者・詳細） | タイトル・作者・説明 |
| レターボックス | 黒帯 |
| Ken Burns効果 | ゆっくりズーム |
| 取り込みキュー | 取り込み中 |
| 出力ディスプレイ | 出力先の画面 |
| 同期オフセット（ms） | 音ズレ補正 |
| エンコード | 動画に書き出す |

## 8. ロゴ

![Fluxlide マーク](../assets/brand/fluxlide-mark.svg)

16:9の角丸の板を3枚、右下へずらして重ねたマーク。スライドが奥から手前へ流れてくる様子を表す。アプリアイコンからファビコンまで、すべてのサイズでこの形を使う。

| 項目 | 内容 |
| --- | --- |
| 形 | 64×64の枠に、34×24・角丸4の板を9pxずつ右下へずらして3枚重ねる |
| 色 | 手前の1枚はコーラル `#E8553A`。奥の2枚は背景に合わせた文字色（明るい背景ではネイビー `#13213B`）を不透明度50%・24%で塗る |
| 単色版 | 3枚とも同じ色で、奥の2枚の不透明度を65%・35%にする |
| ロゴタイプ | Jost（OFL）SemiBold、字間 0。SVGでは文字をパスに変換している |

ファイル:

| ファイル | 内容 |
| --- | --- |
| [`assets/brand/fluxlide-mark.svg`](../assets/brand/fluxlide-mark.svg) | マーク（明るい背景用） |
| [`assets/brand/fluxlide-mark-mono.svg`](../assets/brand/fluxlide-mark-mono.svg) | 単色版。`currentColor` で塗り、初期色はネイビー |
| [`assets/brand/fluxlide-logo.svg`](../assets/brand/fluxlide-logo.svg) | マークとロゴタイプの横組み |

アプリアイコンは、Tauriの実装を始めたときに `tauri icon` でマークから `src-tauri/icons/` に各サイズを生成する。

## 9. 決定事項

2026-10-20のレビューで決めた内容。

| 項目 | 決定 |
| --- | --- |
| 素材の並び | 左に縦一列 |
| 使い方の案内 | 案内ツアーは入れず、サンプルのキャプションに説明を書く |
| 表示時間の初期値 | 10秒 |
