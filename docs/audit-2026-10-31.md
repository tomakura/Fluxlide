# Fluxlide 残件監査（2026-10-31）

> 01〜28の本文は修正前の監査記録。v1.0.1に向けた対応結果を末尾の5章に追記した。本文の「今回」は2026-10-31の洗い出しを指す。

対象は `main` の `9223ac63f3451835599fac9a4279b0f593f62e62`。ローカル、origin/main、公開済み v1.0.0 のタグが同じコミットであることを確認した。製品コードの修正、コミット、インストーラーの再作成、リリースの変更は行っていない。

現行コード・仕様書・自動検査・限定した再現確認から、28項目を整理した。すべての実機条件を網羅した保証ではない。「未記録」と「未実施」、「ソース上の問題」と「実行して再現した問題」を区別する。

優先度は P1＝先に修正、P2＝次の品質確認・配布までに対応、P3＝整備・方針決定。以下の完了条件は、これから行う作業の条件であり、今回達成したという意味ではない。

## 1. 修正する項目（01〜12）

### 01 / P1 / 書き出しを中止・失敗すると既存の保存先まで消す

- **実エンジンで再現。** `export_slideshow` はエラーになると、まだ今回の出力を書いていなくても `remove_file(out)` を呼ぶ。
- 既存ファイルを用意し、開始時点で中止した結果は `Err(Export("the export was cancelled"))`、`existing_output_survived=false`。
- 対象: [export.rs](../crates/fluxlide-engine/src/export.rs) 156〜200行、`mux` も既存出力に直接 `-y` で書く。
- 完了条件: 完成した出力を一時ファイルから置き換える。開始前・描画中・音声処理中・結合失敗・中止のすべてで、既存出力が元の内容のまま残る。成功時だけ置換する。

### 02 / P1 / 手動送りの作品の動画書き出しが終わらない

- **実エンジンで再現。** `play_once()` は周回終了の扱いだけ変え、`advance_mode` は `Manual` のまま。時間が進んでも次のスライド・終了へ進まない。
- 同じ写真1枚・表示200ms・カット・10fpsで、自動送りは3フレームで正常終了。手動送りは100フレームでも `finished=false` で、検証側の上限で中止した。
- 対象: [slideshow.rs](../crates/fluxlide-engine/src/slideshow.rs) 402、504〜506、863〜867行、[export.rs](../crates/fluxlide-engine/src/export.rs) 246行。
- 完了条件: 上映の手動設定を保ちながら、書き出しは定義された表示時間で1周して終わる。写真だけ・動画混在・最後で停止・ループ設定を試験する。

### 03 / P1 / Tokio 1.54.0 の既知の問題を解消する

- **cargo audit と一次情報で確認。** [Cargo.lock](../Cargo.lock) 4709行からの `tokio 1.54.0` に `RUSTSEC-2026-0384` が該当する。Tauri経由の依存。
- マルチスレッドランタイムの `Interval` に競合と use-after-free があり、修正版は `>=1.54.1`。Fluxlideで該当経路を実際に通るかは未確認。クラッシュを再現したという報告ではない。
- 根拠: [RustSec advisory](https://rustsec.org/advisories/RUSTSEC-2026-0384.html)。`Sleep` / `Timeout` はこの問題の対象外。
- 完了条件: 修正版へlockを更新し、3OSのチェックを通す。`cargo audit` でこの指摘が消える。

### 04 / P1 / 編集送信の完了と画面遷移・保存表示をそろえる

- **IPCを差し替えた実フロントエンドで再現。** 1件目の編集応答を保留して続けて入力し、ホームへ戻ると `closeProject` が編集待ちを追い越す。後続編集は送られず、保持した保存状態は変更前のまま。
- その送信待ちの間にも表示は「自動保存済み」。Rust本体を使うネイティブE2Eは未実施。
- 対象: [show.svelte.ts](../src/lib/show.svelte.ts) の編集キュー、[+page.svelte](../src/routes/+page.svelte) の `home` / `start`、[ExportDialog.svelte](../src/lib/components/ExportDialog.svelte) の `start`、[Editor.svelte](../src/lib/components/Editor.svelte) の保存表示。
- 完了条件: ホーム・終了・上映・書き出しの前に対象セッションの編集完了を保証する。送信待ち・保存成功・保存失敗を正しく表示し、連続入力直後にも最後の編集が保存・上映・出力に入る。

### 05 / P1 / ファイル設定画面の保存失敗を知らせ、閉じる前に回復できるようにする

- **エラー非表示はIPCモックUIで再現。** `saveError="disk full"` の応答でも、ファイルごとの設定画面にエラーが出ない。`open.error` の表示も通常の編集画面側にしかない。
- **回復経路の不足はソース確認。** `Session::save` は失敗を保持するが、明示的な再保存はなく、`close_project` はセッションを破棄する。保存失敗のまま閉じるとメモリ上の変更を失う。既存テストも、別の編集（undo）で保存し直す形。
- 対象: [Editor.svelte](../src/lib/components/Editor.svelte) 113〜158行、[FileSettings.svelte](../src/lib/components/FileSettings.svelte)、[session.rs](../src-tauri/src/session.rs) 199〜205行、[editor.rs](../src-tauri/src/editor.rs) の `close` / `close_project`。
- 完了条件: 両方の編集画面に失敗を出し、理由を読める。保存先の問題を直して再試行でき、未保存のまま終了・作品切替を行う場合は変更が失われることを明示する。

### 06 / P2 / BGM終了時のファイル解放とテスト失敗を直す

- **Windowsで2回再現。** 全体テストと単独テストの両方で `bgm::tests::next_and_pause_and_resume_work_on_the_playing_music` が失敗。
- [bgm.rs](../crates/fluxlide-engine/src/bgm.rs) 1994行のテストフォルダ削除で OS error 32（別のプロセスが使用中）。一時ファイルの後片付けでの失敗であり、再生品質の失敗とは分ける。
- `Bgm::drop` はcontrollerをjoinするが、[media/music.rs](../crates/fluxlide-engine/src/media/music.rs) のデコードスレッドの完了は同期的に待っていない。どのハンドルが残るかは追加調査が必要。
- 完了条件: BGM・ミキサー・FFmpegの終了順を明確にし、終了直後に素材を解放できる。待ち時間を足すだけで隠さず、Windowsで単独・全体テストを繰り返して通す。

### 07 / P2 / 1画面時の上映開始予約を画面移動で取り消す

- **IPCモックUIで再現。** 2.5秒の案内中にホームへ戻っても `startPresentation` が呼ばれた。その時点の作品は閉じている。
- 対象: [+page.svelte](../src/routes/+page.svelte) 49〜53行。予約を解除せず、作品・セッションも照合しない。
- 完了条件: ホーム・作品切替・キャンセル・コンポーネント破棄で予約を解除し、案内中の連打でも1回だけ正しい作品を開始する。

### 08 / P2 / 編集画面以外でも書き出し完了を知らせる

- **ファイル設定画面ではIPCモックUIで再現。** 完了イベント後もダイアログは0個、編集へ戻ってから1個になる。ファイル設定中は進捗・中止の入口も消える。
- **ホーム・上映中はソース確認。** 完了ダイアログを開く処理が `Editor` にあり、再マウント時は既存の完了を `seenFinish` として扱うため、そこでの完了は自動通知されない。
- 対象: [Editor.svelte](../src/lib/components/Editor.svelte) 43〜49、113〜152行、[exporting.svelte.ts](../src/lib/exporting.svelte.ts)。
- 完了条件: ファイル設定・ホーム・上映中の各状態で、進捗と完了・失敗が一度届く。上映映像を妨げずに操作画面で確認・中止できる。

### 09 / P2 / Linux同梱版の出力コーデックと製品説明を一致させる

- **ビルド設定と選択処理で確認。** LinuxのLGPL構成では外部のH.264エンコーダを追加せず、選択候補の最後は `mpeg4`。条件がそろうとH.264ではなくMPEG-4 Part 2へ進む。
- [screens.md](screens.md) の「MP4（H.264・AAC）だけ」と一致しない。MP4というコンテナであることと、H.264であることは別。
- 対象: [build-ffmpeg.sh](../scripts/build-ffmpeg.sh) 34〜68行、[export.rs](../crates/fluxlide-engine/src/export.rs) 40〜50、121〜135行。
- 完了条件: Linuxで採用する方式を決め、同梱版から実際に書き出したファイルをffprobeで確認し、UI・README・対応プレーヤーの説明をそろえる。

### 10 / P2 / 「最大ファイルサイズ」とビットレート設定の意味を正す

- **ソース確認。** 見積もりは指定ビットレートを使う一方、`libx264` はCRF 18、`mpeg4` は固定の `-q:v 2` を使い、指定ビットレートを反映しない。したがって表示値を上限とは保証できない。
- 対象: [export.rs](../crates/fluxlide-engine/src/export.rs) 138〜149行、[src-tauri/src/export.rs](../src-tauri/src/export.rs) 123〜135行、[ExportDialog.svelte](../src/lib/components/ExportDialog.svelte) 139〜143行。
- 完了条件: 容量を制御するならエンコーダの設定へ反映する。目安を示すなら「最大」をやめ、実際の方式で精度を検証する。

### 11 / P2 / 初期状態の取得失敗を画面に出す

- **ソース確認。** 起動時の `api.showState().then(...)` に失敗処理がなく、`screen="loading"` のまま。loadingを描く分岐もない。
- 対象: [+page.svelte](../src/routes/+page.svelte) 23〜27、78〜84行。
- 完了条件: IPC失敗時に原因と再試行の入口を表示し、白い画面で止まらない。失敗を注入したUI試験を追加する。

### 12 / P2 / 設定ファイルの破損・読み取り失敗を初回起動と区別する

- **ソース確認。** [settings.rs](../src-tauri/src/settings.rs) 82〜87行は、存在しない・読めない・JSONが壊れている、のすべてを既定値にする。通知はなく、次の更新で元の設定を置き換える可能性がある。
- 影響するのは音ズレ補正、出力画面、外部作品の最近の一覧。作品のDBそのものを削除する処理ではない。
- 完了条件: 初回の未作成は通常処理とし、既存設定の異常は明示する。壊れた元データを残し、利用者が回復方法を選べる。
