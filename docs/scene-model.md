# スライドショーのデータ構造（シーン定義）

> 決定日: 2026-10-21。[完成までの手順](roadmap.md)の段階2の1番。型は [`crates/fluxlide-engine/src/show.rs`](../crates/fluxlide-engine/src/show.rs)、タイムラインどおりに再生する処理は [`slideshow.rs`](../crates/fluxlide-engine/src/slideshow.rs) にある。

## 1. 目的

上映、管理画面のプレビュー、動画への書き出しが、同じデータを読んで同じ時刻に同じ絵を出すようにする（[概要](overview.md)の4.3）。そのために、スライドショーを表すデータの形と、そこから「どのスライドが何秒から何秒まで出るか」を決める規則を決める。

## 2. 全体の形

データは2段に分ける。

| 段 | 型 | 作る所 | 使い道 |
| --- | --- | --- | --- |
| スライドショーの定義 | `ShowDefinition` | 管理画面で編集する | プロジェクトへの保存、webviewとのやり取り（JSON）、元に戻す |
| タイムライン | `Timeline` | 定義からエンジンが計算する | 上映、プレビュー、書き出しが、各スライドの開始・終了の時刻を読む |

定義はGPUの物も、管理フォルダの外のパスも持たない。そのため、そのまま保存でき、JSONにでき、2つを比べて変更を見つけられる。

```
ShowDefinition
├─ title
├─ assets: Asset[]        素材（管理フォルダにコピーした写真・動画）
├─ slides: Slide[]        並び順のスライド。素材をIDで指す
├─ look: Look             見た目（全スライド共通の設定）
├─ music: Music           音楽
└─ playback: Playback     再生方法
```

## 3. 決めたこと

### 3.1 利用者から見た意味（2026-10-21に決定）

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| スライドのトランジション | **そのスライドに入るとき**に使う。最初のスライドは黒から入る | 並びの各行に「このスライドはフェードで入る」と表示でき、直感的。PowerPointと同じ考え方 |
| 表示時間 | **トランジションを含めない**。設定した秒数は写真がはっきり見えている時間で、前後のトランジションはその外側に足す | 設定した数字と見た目の感覚が合う |
| 動画の範囲 | 開始・終了位置を持つ（`VideoOptions`）。**編集画面で指定できるようにする**（段階3） | 長い動画の一部だけを流したい場面に対応する |

### 3.2 技術的な判断

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 時間の単位 | ミリ秒の整数 | 保存と比較で小数の誤差が出ない。フレームの時刻への変換はエンジンが行う |
| 素材の指し方 | ID（`AssetId`）。ファイルは管理フォルダ内のファイル名だけを持つ | 素材は管理フォルダにコピーする（概要の4.7）。フォルダの場所を持たないので、プロジェクトを移動できる |
| タイトル・作者・説明 | 素材が持つ（`AssetMeta`） | 概要の4.6で素材ごとに登録する。同じ素材を2回並べても同じ説明になる |
| スライドごとの設定 | 表示時間、トランジションとその長さ、キャプションの表示、ゆっくりズーム、表示位置、動画の範囲と音量。`None` のものは見た目の設定に従う | [画面草案](ui-draft.md)の「写真・動画」タブの項目に合わせた |
| 全体の設定 | 表示時間の初期値（10秒）、トランジション（フェード、1秒）、縦横比の扱い（ぼかし背景）、キャプションのデザイン、ウォーターマーク、カスタムトランジション（WGSL） | 画面草案の「見た目」タブと決定事項に合わせた |
| 取り込みの状態 | 素材が「取り込み中・使える・失敗」を持つ。進み具合は保存しない | 取り込み中もスライドを並べて説明を書けるようにする。進み具合は取り込みの間だけの情報 |
| 音楽の場所 | フォルダまたはファイルのパス。コピーしない | フォルダに曲を足すと次の上映から流れる（画面草案の音楽の決定）。容量の大きい曲を複製しない |
| 音ズレ補正 | 定義に入れない。アプリの設定として機器ごとに持つ | 会場の機器の性質で、スライドショーの内容ではない。書き出しにも使わない（概要の4.9） |
| 再生方法 | 自動・手動、ループ・停止、並び順・シャッフルを定義に持つ | 出力先の選択画面で選び、「次回もこの画面を使う」ために残す |
| 保存形式の版 | `version` を持つ | 形が変わったとき、古いプロジェクトを変換して読めるようにする |
| JSONの名前 | camelCase。種類のある値は `kind` などの名前の付いた形（`{"kind": "fade"}`） | TypeScript側でそのまま扱いやすい |

## 4. タイムラインの規則

1周分のスライドを、再生時刻の上に並べる。

```
            入り      はっきり見える（写真: 表示時間）   出 = 次の入り
スライド1  |=======|---------------------------------|=======|
スライド2                                            |=======|------------|====
           ^開始                                     ^スライド2の開始
```

- 各スライドは、入りのトランジションの開始（`start_ms`）、入りの長さ（`enter_ms`）、次のスライドが入り始める時刻（`leave_ms`）、消える時刻（`end_ms`）を持つ。
- 写真: `leave_ms = start_ms + 入りの長さ + 表示時間`。
- 動画: 指定した範囲を1回流す。入りと出のトランジションは範囲の最初と最後に重なる。`end_ms - start_ms` が範囲の長さになる。
- 動画の前後のトランジションは、範囲の半分を超えないよう短くする。
- 「カット」（トランジションなし）は長さ0。
- 最後のスライドのあとは、見た目の設定の長さで黒にフェードする。書き出しと、ループしない上映の終わりにあたる。ループする上映では、最後のスライドの `leave_ms` から次の周を始める。
- 使えないスライドは飛ばし、理由を返す: 素材がない、取り込み中か失敗、動画の長さが分からないか範囲が空。
- 順番は呼び出す側が渡す。シャッフルでは、上映が周ごとに新しい順番を作って渡す。
- 手動で進める上映では、表示時間は使わず、操作されたときに次のスライドへ入る。トランジションの種類と長さは同じものを使う。

## 5. エンジンでの再生（2026-10-21に決定）

`Slideshow` は定義を受け取り、1周ごとに `Timeline::build` でタイムラインを作って、その時刻どおりに進める。上映、プレビュー、書き出しは、どれもこの型を通して再生する。

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 時刻の基準 | 各スライドは、実際に入り始めた再生時刻を基準に持つ。入りの進み具合、次が入り始める時刻、ゆっくりズームは、タイムラインの相対時刻（`start_ms` からの差）で計算する | 遅れたときに、あとのスライドをまとめてずらせる |
| 読み込みが遅れたとき | 今のスライドを出したまま待ち、間に合ったら入りの最初から始める。待った分だけ、後ろのスライドがすべて遅れる。遅れは統計（`late_transitions`、`longest_wait_ms`）に残す | 黒や途中からのトランジションを出さない（相談して決定） |
| 書き出し | 時刻を止めて待つ（`is_waiting`）。待っても再生時刻が進まないので遅れは0になり、ファイルはタイムラインどおりになる | 書き出しの結果を、読み込みの速さに左右されないようにする |
| 読み込めなかったスライド | 飛ばし、次のスライドがその時刻に入る。1周分のスライドが続けて失敗したら、試すのをやめる | 上映を止めない |
| 周の終わり | ループする上映は、最後のスライドの `leave_ms` から次の周を始める。シャッフルでは周ごとに並べ直す。「停止」は最後のスライドを出したままにする。書き出し（`play_once`）は黒にフェードして終わる | 4章の規則に合わせた |
| 動画の範囲 | 映像と音声の ffmpeg に `-ss` と `-t` を入力のオプションとして渡し、範囲の先頭を時刻0として扱う。音量は `VideoOptions.volume` を、トランジションに合わせた音量に掛ける | 映像と音声の時刻の基準を同じにする |
| カスタムトランジション | 始めるときにすべてコンパイルする。失敗したものはフェードに置き換え、エラーを統計に残す | 上映中にシェーダーのエラーで止めない |

管理画面の試作は、選んだファイルの一覧から `media_assets` コマンドで素材を作り（動画は ffprobe で長さを測る）、定義を組んで送る。素材の取り込み（段階2の3番）ができるまでは、素材の `file` に元のファイルの絶対パスを入れ、管理フォルダは空にしておく。

## 6. まだ決めていないこと

- **保存の形（段階2の2番）**: SQLiteに、素材とスライドを表に分けて持つか、定義をJSONのまま持つか。元に戻す仕組みと合わせて決める。
- **管理画面とのやり取り（段階2の4番）**: 定義を丸ごと送るか、変更だけを送るか。TypeScriptの型をRustから自動で作るか。今は使う部分だけを手で書いている（`src/lib/show.ts`）。
- **手動で進める上映**: `Advance::Manual` はまだ再生に反映していない。上映中の操作（段階3の4番）と合わせて作る。
- **動画の範囲の指定**: 編集画面で開始・終了位置を指定する画面（段階3）。
- **ゆっくりズームの初期値**: 見た目の設定に「すべての写真にゆっくりズームをかける」を入れるか。
