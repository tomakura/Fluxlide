# 技術検証: キャプション、ウォーターマーク、トランジション、日本語の文字描画

> 実施日: 2026-10-21。Linux（クラウド上のコンテナ、GPUなし）で、ソフトウェアのVulkan（Mesaのllvmpipe）を使い、自動テストと見本画像で確認した。実際のGPUと上映ウィンドウでは確かめていない。

## 1. 目的

[技術選定](tech-stack.md)の「最初に検証する技術課題」3番（カスタムトランジション・キャプション・透かしを両モードで表示できるか）について、次を決める。

- 上映（ウィンドウ）と書き出し・プレビュー（画面外）で同じ描画を使う構成
- トランジションの描き方と、利用者が書くWGSLの決まりごと
- キャプションとウォーターマークの描き方
- 日本語の文字描画の方式（フォントの読み込み、文字の配置）

## 2. 方式

### 描画の構成

描画を `Compositor` にまとめ、描き先を問わないようにした。上映ウィンドウ（`Presenter`）も画面外のテクスチャ（`OffscreenTarget`）も同じ `Compositor` で描くため、上映、書き出し、プレビューの見た目が同じになる。

1フレームは次の順で描く。

1. 写真や動画のフレームを、出力の大きさの黒い「スライド」に置く。縦横比が合わないときの置き方は3種類（`Fit`）: 全体を見せる（黒帯）、隙間なく埋める（はみ出しを切る）、全体を見せて背景にぼかした同じ絵を敷く。ゆっくりズーム用に拡大と移動（`Transform`）も指定できる。
2. トランジション中は、2枚のスライドを画面外のテクスチャに描き、トランジションのシェーダーで合成する。トランジション中でなければ、1枚を直接描く。
3. キャプションとウォーターマーク（`Overlay`）を最後に重ねる。トランジションで絵が動いても、重ねた物は動かない。

色の合成はすべてリニアの光で行う。描き先をsRGBのテクスチャにして、読み書きのときにGPUが変換する。

### トランジション

利用者が書くのは `transition` 関数だけとし、エンジンが入り口や画像の読み取りを後ろに足す。

```wgsl
fn transition(uv: vec2<f32>, progress: f32) -> vec4<f32> {
    return mix(from_color(uv), to_color(uv), progress);
}
```

| 名前 | 内容 |
| --- | --- |
| `uv` | 出力の左上が (0, 0)、右下が (1, 1) |
| `progress` | 0（開始）から1（終了）。緩急は付けない。付けるかはシェーダーが決める |
| `from_color(uv)`、`to_color(uv)` | 出ていく絵と入ってくる絵の、その位置の色（リニア）。範囲外は黒 |
| `fx.resolution`、`fx.aspect` | 出力の画素数と縦横比 |
| `fx.params` | 4つの数値。トランジションごとの設定（向きなど）に使う |

`fx`、`FxUniforms`、`from_color`、`to_color`、`fx_` で始まる名前は予約する。利用者のコードを先頭に置くので、コンパイルエラーの行番号は利用者のコードの行番号と一致する。エラーは最初のフレームを描く前（読み込んだ時点）に、コンパイラのメッセージ付きで返す。

組み込みのトランジションも同じ形で書いた: フェード、スライド（上下左右）、ワイプ（上下左右、境目はぼかす）、ズーム。

### キャプション

- タイトル、作者、説明の3つ。大きさはすべて出力の高さに対する割合で決め、プレビュー、プロジェクター、書き出しのどの大きさでも同じ見た目にする（1080pで約44、20、22px）。タイトルを主に、作者名と説明文は控えめにする。
- デザインは3種類: 下端の暗いグラデーションの上に白い文字（既定）、縦線と影付きの白い文字（背景なし）、右下の明るいカードに暗い文字。
- 説明は3行まで。超えた分は「…」で切る。
- 素材が切り替わるときは、前のキャプションをトランジションの前半で消し、次のキャプションを後半で出す。

### ウォーターマーク

- 文字（字間を広げ、細い枠で囲む）か、透明部分のある画像（ロゴ）。
- 四隅のどれかに、同じ余白で置く。不透明度を指定できる。トランジション中も位置と不透明度は変わらない。

### 日本語の文字描画

| 候補 | 内容 | 判断 |
| --- | --- | --- |
| **cosmic-text（swashで描画）** | 純Rust。文字の配置（シェーピング）、行の折り返し、可変フォントに対応。MIT または Apache-2.0 | **採用** |
| glyphon | cosmic-textの結果をwgpuで描く。グリフのアトラスを管理してくれる | キャプションは素材ごとに1回描けば済むため、アトラスまでは要らない |
| OSの文字描画（DirectWrite、Core Text、FreeType） | OS標準の見た目 | OSごとに実装が要り、OSで見た目が変わる |

- 文字はCPUで覆い率のマスク（8bit）にし、GPUではそのマスクを色と合わせるだけにした。キャプションは素材が変わるときに1回作れば済み、毎フレーム描き直さない。
- フォントは同梱の **Noto Sans JP**（可変フォント、太さ100〜900）だけを使い、インストール済みのフォントは読まない。どのOSでも、上映でも書き出しでも、同じ画素になる。
- フォントは `include_bytes!` で実行ファイルに埋め込んだ。リソースファイルの場所に依存しないため。
- 行頭に来てはいけない句読点（「。」「、」「）」など）が行頭に来ないことを確かめた（cosmic-textの折り返しによる）。

## 4. 結果

### 自動テスト

`cargo test -p fluxlide-engine` で、画面外に描いて読み戻した画素を調べた。

| 確認項目 | 結果 |
| --- | --- |
| 組み込みのトランジション | どれも出ていく絵で始まり、入ってくる絵で終わる。スライドとワイプは指定した向きに動く |
| 利用者のWGSL | `fx.params`、`fx.resolution`、`fx.aspect` を受け取って動く。壊れたコードは最初のフレームより前に、コンパイラのメッセージと利用者のコードでの行番号付きで失敗する |
| 色 | sRGBで出力され、合成はリニアで行われる。同じシーンは何度描いても同じ画素になる |
| 置き方、拡大と移動 | 縦長の写真を横長の出力に、3種類の置き方で期待通りに置く |
| キャプション | デザインごとの位置に描かれ、不透明度に従う。説明は3行で切る。出力の大きさに合わせて文字の大きさが変わる |
| ウォーターマーク | 四隅で同じ余白。トランジション中も位置と不透明度が変わらない |
| 日本語 | 豆腐（□）にならない。行頭に閉じ括弧や句点が来ない。可変フォントの太さが効く |
| 読み戻し | 行の長さが256バイトの倍数でない大きさでも、画素がずれない |
| スライドショー | キャプションとウォーターマークが素材の切り替えに合わせて出入りする |

### 見本画像

`cargo run --release -p fluxlide-engine --example render_samples -- <出力先>` で、トランジションの途中、キャプションの各デザイン（明るい写真、暗い写真）、ウォーターマークの四隅、置き方の見本を1920×1080で書き出し、目で確かめた。

- 日本語の文字はつぶれず、なめらかに描ける。
- 「縦線と影付きの白い文字」のデザインは、霧のような明るい写真の上で読めなかった。影のぼかしを小さくし（1080pで11px→6px）、濃くした（強める係数を2.5→4.0）。明るい写真でも読めるようになったが、白い背景ではほかの2つのデザインより読みにくい。
- llvmpipeでの描画にかかる時間はCPUの性能で決まるため、GPUでの性能の目安にはならない。性能は[動画への書き出し](spike-export.md)の確認と、実際のGPUを持つ機械で測る。

- フォントの埋め込みで実行ファイルが約9.6MB大きくなる。日本語の常用漢字などに絞ったサブセットにするか、配布物の大きさを見て決める。
