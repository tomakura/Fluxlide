## 段階1: 技術検証を終えて方式を確定する

1. WindowsとLinuxの実機で、1番・2番・4番の試作を確かめる。HDMIでつないだ外部ディスプレイも確かめる。
2. 技術課題3番として、キャプション、ウォーターマーク、トランジションを描画エンジンで描く。日本語の文字描画の方式（フォントの読み込み、文字の配置）を決める。
3. 技術課題5番として、動画への書き出しを試作する（画面外で描いたフレームをffmpegでエンコードする）。上映との見た目の差、CPU・GPU・メモリの使用量を測る。
4. 管理画面の中にプレビューを出す方式を決める。描画エンジンの映像をwebviewにどう載せるかは未調査である。
5. 技術課題4番の残りとして、BGM、動画再生中にBGMを下げる処理、Bluetooth向けの音ズレ補正を試作する。
6. LGPL版のFFmpegを3OS分用意し、Tauriの `externalBin` で同梱する。ライセンスの表記と、H.264の特許の扱いを確かめる。
7. 結果を[技術選定](tech-stack.md)に反映し、方式を確定する。

## 段階2: 土台を作る

1. スライドショーのデータ構造（シーン定義）を決める。上映、プレビュー、書き出しが同じものを読むようにする。型とタイムラインの規則を決め、試作の `Slideshow` をタイムラインから時刻を読む形に置き換えた（[データ構造](scene-model.md)）
2. プロジェクトをSQLiteに保存し、自動保存と「元に戻す」を入れる。済み（[保存と取り込み](project-storage.md)）
3. 素材の取り込みを作る。管理フォルダへのコピー、取り込み中の表示、失敗したときの扱いを含む。済み（取り込み中の表示は段階3の画面で作る）
4. 管理画面と描画エンジンの間のやり取り（コマンドとイベント）の形を決める。済み（[やり取り](ipc.md)）

## 段階3: 最小限の製品（MVP）

写真と動画を並べて上映し、保存できる版を作る。

1. ホーム画面（新規作成、最近のスライドショー）
2. 編集画面の「写真・動画」タブ（並べ替え、表示時間、タイトル・作者・説明、動画の開始・終了位置）
3. 出力先の選択画面
4. 上映中の操作（前へ・次へ・一時停止・暗転、キー操作、終了の確認）
5. 上映画面の開始前と終了後の画面

## 段階4: 演出と音楽

1. 「見た目」タブ（キャプションのデザイン、ウォーターマーク、縦横比が合わない写真の表示方法、トランジションの種類、ゆっくりズーム）
2. カスタムトランジション（WGSL）の読み込み
3. 「音楽」タブ（BGMのフォルダ指定、シャッフル、動画中のフェード、テスト音による音ズレ補正）
4. 再生方法（自動・手動、ループ、シャッフル）

## 段階5: 動画への書き出し

1. 用途から選ぶ書き出し画面（テレビ、動画サイト、スマホ、高画質）
2. ファイルサイズと所要時間の目安、進み具合の表示、中止の処理
3. 上映との見た目の差の確認

## 段階6: 品質を上げる

1. ディスプレイの抜き差し、出力機器の切り替え、壊れた素材への対応
2. 長時間の連続再生（サイネージ用途）でのメモリ使用量と安定性
3. HEIC・HEVC、縦向きの動画、色プロファイル、HDRなどの素材への対応範囲を決める
4. 自動テストの拡充と、3OSでの手動確認項目の一覧

## 段階7: 配布（v1.0）

1. macOSの署名と公証、Windowsのコード署名
2. `.github/workflows/release.yml` でのリリース作業を実際に通す（現在は未検証）
3. FFmpeg、フォント（Noto Sans JP、Jost）などのライセンス表記
4. 使い方を兼ねたサンプルのスライドショーとREADMEの更新
5. バージョンタグを付けてGitHub Releasesに公開する
