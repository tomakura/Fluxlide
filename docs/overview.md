# Fluxlide（フラックスライド）— ソフトウェア概要

> ステータス: 企画・設計段階。本書に記載した機能は実装済みではなく、開発予定の要件です。

## 1. 概要

**Fluxlide** は、写真・動画を組み合わせ、キャプション、ウォーターマーク、カスタムトランジション、BGMを設定できるスライドショー制作・再生ソフトウェア。

作成したスライドショーは、動画ファイルに書き出せるほか、**OBSなしで指定した外部ディスプレイに独立して全画面出力**できる。展示会、イベント、デジタルサイネージ、プレゼンテーションなどでの利用を想定する。

**対応対象:** Windows / Linux / macOS

## 2. 主要機能（開発予定）

| 分類 | 予定している機能 |
| --- | --- |
| メディア管理 | 写真・動画の読み込み、並び替え、表示時間、タイトル・作者・詳細の編集 |
| ファイル取り込み | アプリ管理領域への自動コピー、取り込みキューと進捗、取り込み中のキャプション編集 |
| キャプション | タイトル・作者・説明の配置、デザイン、アニメーション |
| ウォーターマーク | ロゴ・画像・テキストをトランジション中も常時表示 |
| トランジション | フェード、スライド、ズーム、カスタムシェーダー等 |
| アニメーション | メディア・文字の位置、スケール、不透明度などの変更 |
| 音声 | BGM再生、動画再生中のBGMフェードアウトと終了後の復帰、動画音声の音量調整 |
| 音声同期 | Bluetooth機器向けのミリ秒単位の同期オフセット調整 |
| 再生制御 | 自動再生、ループ、シャッフル、手動送り・戻し |
| マルチディスプレイ | 表示先の選択と、操作画面から独立した全画面出力 |
| 動画出力 | MP4等のファイルへの書き出し |
| プロジェクト | メディア情報・設定・構成の保存と再編集 |

## 3. 想定画面構成

- **メディア管理:** 素材の一覧、追加・削除、タイトル・作者・詳細情報の編集
- **取り込みキュー:** 待機中・コピー中・完了・失敗の状態と進捗。処理中もメタデータとキャプションを入力できる
- **プレビュー:** 実際の出力を想定した映像と文字・ウォーターマークの確認
- **タイムライン／スライド一覧:** 順序、表示時間、トランジションの編集
- **プロパティ:** 個別素材のレイアウト、キャプション、効果の設定
- **音声設定:** BGM、動画音声、フェード、同期補正
- **出力コントロール:** 再生、一時停止、外部画面への出力、動画書き出し

## 4. 重要な要件

### 4.1 外部ディスプレイへの独立全画面出力

管理・編集画面を表示したまま、選択したモニターには再生映像だけを全画面表示する。OBS等の外部ソフトを必須にしない。接続解除やディスプレイ構成の変化にも可能な範囲で安全に対応する。

### 4.2 シームレスな再生

写真・動画が混在する構成でも、先読みや素材の事前準備によって停止、黒画面、無音をできるだけ避ける。

### 4.3 再生と書き出しの一貫性

リアルタイム再生と動画書き出しで同じシーン定義・タイミング・エフェクト設定を使う。完全な描画一致は実装・検証段階の目標とし、OSやコーデックごとの差を評価する。

### 4.4 カスタマイズ性

トランジション・キャプションデザインはテンプレートから選べ、独自エフェクトを追加できる拡張構造を目指す。

### 4.5 メディアのメタデータ

メディア管理画面内で素材ごとに**タイトル・作者・詳細**を登録・編集できる。メタデータはプロジェクトに保存し、キャプションにも流用できる。

### 4.6 アプリ管理フォルダへの自動コピー

取り込んだ素材はOSのアプリデータ領域等に設ける**Fluxlide管理フォルダに自動でコピー**し、取り込み完了後は元ファイルの移動・削除に影響されない構成とする。コピー失敗・中断時に不完全なファイルを正常な素材として扱わない。

コピーはキュー管理し、待機・進行・完了・失敗と進捗を表示する。**取り込み中でもタイトル・作者・詳細・キャプションの編集を継続できる**ことを要件とする。

### 4.7 BGMと動画音声

スライドショー用のBGMを再生できる。動画の音声を優先するため、**動画再生に入るとBGMをフェードアウトして無音にし、動画終了後にフェードインして戻す**。フェード時間等は調整可能とする。

### 4.8 Bluetooth機器向け音声同期

出力音声と映像の時間差を**ミリ秒単位**で補正できるようにする。Bluetoothの音声遅延を相殺するには、先読みバッファーや映像側の遅延等を組み合わせる必要がある。物理的に過去へ音を送ることはできない。補正値はユーザーが調節でき、原則としてリアルタイム再生のみに適用し、通常の動画書き出しには反映しない。

## 5. 採用予定の技術構成

| 要素 | 方針 |
| --- | --- |
| デスクトップ基盤 | **Tauri 2** |
| UI | **Svelte 5 + TypeScript + Vite** |
| バックエンド | **Rust** |
| データ管理 | SQLiteを第一候補とする |
| リアルタイム映像表現 | WebGL2 / GLSLを第一候補とする |
| エンコード・メディア処理 | FFmpegを候補とする（同梱・ライセンス要検討） |
| 対象OS | **Windows / Linux / macOS（初期から3OS対応を目標）** |
| 自動ビルド・配布 | GitHub Actions / GitHub Releases |

詳しい選定理由、技術的リスク、配布方法については [技術構成・配布方針](tech-stack.md) を参照。

## 6. 製品コンセプト

一般的な動画編集ソフトではなく、**「編集機能を備えた高機能スライドショープレイヤー」**として設計する。素材を登録して順番、キャプション、演出を設定するだけで、そのままディスプレイに出力でき、同じ構成を動画ファイルにも書き出せる。
