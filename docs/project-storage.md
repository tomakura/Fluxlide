# プロジェクトの保存、自動保存、元に戻す

> 決定日: 2026-10-22。[完成までの手順](roadmap.md)の段階2の2番。処理は [`src-tauri/src/project.rs`](../src-tauri/src/project.rs)（保存）、[`history.rs`](../src-tauri/src/history.rs)（元に戻す）、[`session.rs`](../src-tauri/src/session.rs)（編集中の状態）、[`editor.rs`](../src-tauri/src/editor.rs)（管理画面のコマンド）にある。

## 1. 保存の形

1つのスライドショーを1つのフォルダにする（相談して決定）。

```
<アプリのデータフォルダ>/projects/
  └ show-1792648800000/
      ├ project.sqlite   定義（JSON）、題名、枚数、更新日時
      └ media/           取り込んだ写真・動画のコピー
```

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 単位 | 1作品1フォルダ。データベースと素材を同じフォルダに置く | フォルダごと移動・複製・バックアップできる。「ほかの場所から開く」はこのフォルダを開く |
| 置き場所 | 新しい作品はアプリのデータフォルダの `projects/` に作る。フォルダ名は作った時刻 | 保存場所を意識させない（画面草案のA）。題名を変えてもフォルダ名は変わらない |
| 定義の持ち方 | `ShowDefinition` をJSONのまま1行に持つ | 素材とスライドを表に分けると、型を変えるたびに表も変える必要がある。定義は写真の画素を含まないので小さく、丸ごと書いても速い |
| ホーム画面用の列 | 題名、枚数、最初のスライドのファイル、更新日時を別の列に持つ | 一覧を出すときに定義を読まずに済む |
| 版 | 表の形は SQLite の `user_version`、定義の形は `version` で表す。新しい版で作られたものは開かない。定義に `version` がなければ壊れたものとして扱う | 古い形を変換して読むときに、版の分からないものを今の版と取り違えない |

## 2. 自動保存

- 変更のたびに、その場でデータベースに書く。保存ボタンはない（画面草案のB-7）。
- WALモードで書く。書いている途中でアプリが落ちても、最後に書き終えた状態から開ける。
- 保存に失敗したら、理由を管理画面に返す（`saveError`）。次の保存が成功すると消える。
- 取り込みの途中でアプリを閉じた素材は、次に開いたときに「取り込みが途中で止まりました」という失敗にする。書きかけのファイル（`.part`）は消す。不完全なファイルを素材として使わない（概要の4.7）。

## 3. 元に戻す

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 記録の仕方 | 変更の前の定義を丸ごと残す | 定義は小さい。変更ごとに逆の操作を書くより間違いにくい |
| 残す範囲 | 開いている間だけ。最大100回 | 相談して決定。閉じると消える |
| まとめ方 | 同じ入力欄（`group`）への変更が1.5秒以内に続けば1回にまとめる | 1文字ずつ戻ると使いにくい |
| 取り込みの結果 | 元に戻す対象にしない。素材のファイルの情報（状態、大きさ、長さ、音の有無）は別に覚えておき、戻した定義にも重ねる | 戻したときに、コピーが終わった素材が「取り込み中」に戻らないようにする |

## 4. 管理画面とのやり取り

定義はエンジン側（Rust）が持つ。管理画面は変更した定義を丸ごと送り、返ってきた状態を表示する。

| コマンド | 内容 |
| --- | --- |
| `list_projects` | `projects/` の作品を新しい順に返す |
| `create_project(title)` / `open_project(dir)` / `close_project` | 作品を作る・開く・閉じる |
| `show_state` | 開いている作品の状態 |
| `edit_show(show, group)` | 定義を置き換える。`group` は変更した入力欄の名前 |
| `undo_show` / `redo_show` | 元に戻す・やり直す |

どれも `ShowState`（フォルダ、素材のフォルダ、定義、元に戻せるか、やり直せるか、保存のエラー）を返す。
