# 手動の確認項目

> 作成日: 2026-10-22。リリースの前に、各OS（Windows、macOS、Linux）で次を確かめる。自動テストで確かめられないもの（画面の操作、実際の画面と音の出口、機器の抜き差し）を集めた。結果は OS ごとに「済み・日付・機器」を書き足す。

2026-11-01、v1.0.1の修正版をWindows 11 / RTX 4070 Ti / WebView2で確認した。画面は3840×2160（150%）と1920×1080の外部画面2台、音声出力はYamaha AG03MK2。開発実行と配布物の検査を分ける。下のチェック欄は全OSでの完了を意味するため、部分確認だけでは埋めない。

ユーザーの指定により、追加のMac/Linux実機、iPhone撮影素材、機器の抜き差しは用意せず進める。これらと4時間以上のネイティブ上映は未確認として残す。CIの成功を物理機器での確認の代わりとはしない。

## 1. 作る

- [ ] ホーム画面の「＋ 新しいスライドショー」で作品ができ、編集画面になる
- [ ] 写真と動画をホーム画面にドロップすると、新しい作品ができて取り込まれる
- [ ] 取り込み中にコピーの進み具合が出て、その間にタイトルを入力できる
- [ ] HEIC の写真（iPhone で撮ったもの）を取り込める。縦に撮った写真が縦に出る
- [ ] 縦に撮った動画が縦に出る
- [ ] 対応していないファイルは、理由を出して断る
- [ ] スライドを番号の部分でつかんで並べ替えると、置いた位置に入る（上へ・下へ・末尾）。Alt + ↑ ↓ でも動く
- [ ] Ctrl+Z（macOS は ⌘Z）で元に戻り、Ctrl+Shift+Z か Ctrl+Y（macOS は ⌘⇧Z）でやり直せる。入力欄の中では入力欄の取り消しになる
- [ ] 文字を速く打っても、入力欄の文字が戻らない。日本語の変換が途切れない
- [ ] アプリを閉じて開き直すと、最後の状態が残っている（自動保存）
- [ ] 「ほかの場所から開く」で開いた作品が、ホーム画面の最近の一覧に出る

## 2. 見た目と音楽

- [ ] 見た目タブの各設定（デザイン、ウォーターマークの文字・画像、位置、不透明度、大きさ、縦横比、トランジション、表示時間、ゆっくりズーム、文字の大きさ）がプレビューに出る
- [ ] ウォーターマークの画像の選択をやめると、選択欄が元に戻る
- [ ] 間違いのある WGSL を追加すると理由が出て、正しいものはトランジションの一覧に出る
- [ ] 音楽タブで BGM のフォルダを選ぶと曲の一覧が出る。音量を動かしても一覧がちらつかない
- [ ] テスト音で、光と音が同時になるように音ズレ補正を合わせられる。Esc か「テスト音を止める」で止まる

## 3. 上映

- [ ] 「▶ 上映する」で出力先の選択が出る。「各画面に番号を表示」で各画面に番号が出て、3秒で消える。続けて押しても番号が残らない
- [ ] 画面が1台のときは、案内が2.5秒出てから始まる
- [ ] 「上映を始める」を押すと最初のスライドが出る。タイトル画面で追加の開始操作を待たない
- [ ] 前へ・次へ・一時停止・暗転が、操作画面のボタンと上映画面のキー（← → Page Up/Down Space B）で効く。プレゼン用のリモコンでも効く
- [ ] 暗転と復帰が0.4秒で滑らかにつながる。一時停止中やフェード途中の押し直しでも、急に明るさが変わらない
- [ ] 一時停止で BGM も止まり、再開で戻る。一時停止中に次へを押すと、BGM も戻る
- [ ] 動画の音が映像と合っている。音のある動画の間は BGM が下がる
- [ ] 最後のスライドのあとで次へを押すと、終了の画面になる
- [ ] Esc で終わる。画面が2台以上なら操作画面で確認が出る
- [ ] 上映ウィンドウを OS の操作で閉じると（Windows は Alt+F4）、操作画面が編集に戻る

## 4. 機器の抜き差し

- [ ] 上映中に出力先の HDMI を抜くと、一時停止して操作画面に知らせが出る。挿し直すと、その画面に全画面で戻る
- [ ] 上映中に Bluetooth のスピーカーをつなぐと、音がスピーカーに移る。外すと、内蔵のスピーカーに戻る
- [ ] 上映中にイヤホンを挿す・抜くと、音がついていく

## 5. 書き出し

- [ ] 用途を選ぶと、長さ・ファイルの大きさ・かかる時間の目安が出る
- [ ] 書き出したファイルが OS の標準のプレーヤーで再生でき、上映と同じ見た目で、BGM が入り、最後に音も消える
- [ ] 書き出し中にダイアログを閉じても続き、上部の帯に進み具合が出る。終わるとダイアログが開いて知らせる
- [ ] 中止すると途中のファイルが残らない
- [ ] 書き出し中にアプリを閉じると、途中のファイルが残らない

## 6. 長時間

- [ ] ループする作品を、実際の上映ウィンドウで4時間以上流す。止まらず、メモリが増え続けない（Windows はタスクマネージャー、macOS はアクティビティモニタで見る）

### 7.1 v1.0.1の確認結果

修正対象は `fix/audit-1.0.1`。最終的なソースSHAはリリース添付の `release-provenance.json`、3OSの結果は[Actions](https://github.com/tomakura/Fluxlide/actions/workflows/ci.yml)で照合できる。検証時に利用者の作品は変更していない。自作の検証用作品だけを使用した。

| 条件 | 結果と確認方法 |
| --- | --- |
| 新規作成・サンプル取り込み・タイトル保存 | Windows実IPCで作成、6枚の素材ready、UI入力後の保存内容を確認 |
| 高速入力とホーム遷移 | IPC遅延を注入した実Svelte画面で、最後の編集完了まで遷移を待つことを確認 |
| 保存失敗・回復 | ファイル設定画面にも理由と再試行を表示。Rustの保存失敗試験と、フロントの送信失敗・再試行試験あり |
| HEIC・縦動画・不正素材 | Rust試験。実HEVCの通常・タイル・回転付きHEICを追加。iPhone撮影写真は未確認 |
| 並べ替え・取り消し・IME・外部作品 | 自動試験の範囲を除き、今回の実機操作では未確認 |
| 見た目 | GPUで44枚を生成。シンプルなキャプションの白背景と960px幅のホームボタンを修正。全DPI・実写真の網羅ではない |
| ウォーターマーク・WGSL・BGM設定・テスト音 | 既存のエンジン試験を実行。すべての設定を今回実機で操作したとはしていない |
| 出力先選択・上映開始 | Windowsの3台目の外部画面へUIで開始。最初のスライドと操作画面の映像表示を確認 |
| 1画面時の予約 | IPCモックでホーム遷移後に開始されないことを確認。実際の画面切替は未確認 |
| 一時停止・次へ・暗転 | 実IPCで停止→次へで再開、暗転後の映像データのRGB最大値0を確認。キー・リモコン全種類は未確認 |
| BGM停止・音声同期・終端 | WindowsでBGMの停止・素材解放を含む回帰試験成功。実聴での全条件の評価は未確認 |
| 上映終了 | 外部画面の上映を操作画面の確認ダイアログから終了し、編集画面へ復帰 |

| 書き出しの完了・失敗通知 | ファイル設定・ホームはIPC注入、上映中は実書き出しで通知を確認 |
